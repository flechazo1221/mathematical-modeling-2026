## 写作风格

1. 问题驱动，少写泛泛背景，尽快说明决策场景、子问题和评价目标。
2. 工程化、客观、克制；以“本文”为主要叙述主体，避免宣传和口号。
3. 按子问题组织摘要、分析、求解和总结，使方法与结论可沿编号追踪。
4. 方法名与作用同时出现，说明解决的困难、输入输出和适用理由。
5. 公式前说明目的，公式后解释符号、约束、求解和决策含义。
6. 结果落到自然语言方案和关键数值，再讨论意义。

## 句式习惯

- 任务定位：`针对问题一，需要在……约束下确定……。`
- 方法选择：`考虑到……，本文采用……描述/求解……。`
- 定义引入：`令……表示……，则……可表示为……。`
- 公式衔接：`由上述假设与定义，可得……。其中，……。`
- 结果陈述：`计算结果表明，在……条件下，……为……。`
- 图表解释：`由图 X 可见，……随……呈……趋势；当……时……，说明……。`
- 稳健性：`当……在……范围内变化时，……仍保持……，表明结论对……不敏感/存在明显敏感性。`
- 限制说明：`该结论依赖于……假设；当……不成立时，需要重新估计/求解……。`

以中短句为主，一个句子承担一个主要逻辑动作。复杂推导拆为“条件—公式—解释—结论”。“结果表明”“由图可见”后必须跟可核验的趋势、比较或数值。少用“显然”“效果很好”“意义重大”等无法核验的措辞。术语、符号和单位服从术语表。

## 章节结构

默认逻辑顺序为：标题；摘要与关键词；问题重述；问题分析；模型假设；符号说明；按子问题展开的模型建立与求解；敏感性、稳健性或误差分析；模型评价与推广；参考文献；附录。官方模板可以改变标题和顺序。

每个子问题优先采用：

```text
结论目标 → 建模依据 → 变量与假设 → 数学模型 → 求解步骤
         → 真实结果 → 结果解释 → 验证/边界 → 本题答案
```

不要重复题目原文、拆出空洞小节或把完整代码放入正文。

## 摘要

首段简要交代研究对象、总目标和方法链。随后按问题一至问题 N 写清核心困难、模型或算法的作用、最关键的定量结果以及必要的基线、误差或稳健性结论。所有模型名、参数、数值和结论必须能在正文精确定位。关键词由核心方法和领域对象决定，不机械凑数。

## 实验与求解描述

每次计算、仿真、优化或敏感性实验按以下顺序写：

1. 目的：验证或解决什么。
2. 输入与口径：来源、样本规模、单位、预处理和版本。
3. 设置：关键参数、随机种子、初值、停止条件和必要环境。
4. 基线与比较：简单方案、原方法、边界或替代模型。
5. 输出：关键数值、方案、误差、区间、可行性或收敛结果。
6. 解释：结果为何出现，对题目决策意味着什么。
7. 验证与限制：敏感性、稳健性、失败案例和适用范围。

正文采用“设定—运行—结果—解释”的闭环，不写程序操作日志。模拟数据必须说明原因、生成机制和与真实问题的差距，不能伪装成真实数据结论。

## 图表描述

正文先说明图表回答的问题，再放置图表。图后指出趋势、拐点、差异或收敛位置，给出关键数值或区间，并转化为模型判断或决策选择。表前说明比较口径，表后指出关键差异和选择理由；编码方案必须翻译成自然语言。

不要求“一题一流程图”或“一结论一张图”。图表数量和图型由证据需要决定。不得使用难以阅读的三维装饰图、低分辨率截图、无单位坐标或仅作装饰的图。“由图可见”不能替代统计检验和定量比较。

## 生成契约

使用客观、工程化、问题驱动的中文学术表达。按子问题保持可追踪编号；摘要写清方法作用、真实定量结果和验证结论；正文完成结论目标、建模依据、变量与假设、数学模型、求解步骤、真实结果、结果解释、验证和适用边界，并以自然语言回答题目。禁止空泛评价、宣传语言、无证据创新、虚构数据、复制范文原句以及用图表或算法名称堆砌内容。

## 不固化的弱写法

不机械模仿：大段重复题目、冗长教科书定义、凭曲线目测宣称有效、弱化模拟数据局限、无依据推广、正文堆代码截图、图题过短、坐标缺单位、难读三维图和套话式优缺点。
